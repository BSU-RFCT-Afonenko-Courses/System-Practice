Знакомая ведомость

S07 2 keep

Сводка включает пригодные keep, упорядоченные по количеству, затем коду при равенстве. Сохраняются Code и Units; входы неизменны.

Представление входа

PowerShell читает inputs/readings.csv: заголовок Code,Units,State и записи через запятую. fish читает inputs/readings.txt: строки Code|Units|State без заголовка. Данные имеют UTF-8 без BOM и LF.

наблюдения → отбор keep → порядок Units,Code → поля Code,Units

В PowerShell поля становятся свойствами объекта. В текстовой записи их положение задаёт разделитель. Внутри полей этого набора нет пробелов, кавычек, разделителей и переводов строки.

Создайте results: New-Item -ItemType Directory -Path results в PowerShell либо mkdir results в fish.

Импорт PowerShell

Какой тип имеет Units после чтения CSV? Найдите его через Get-Member и определите, какие объекты пропустит условие отбора.

$raw = Import-Csv -LiteralPath inputs/readings.csv -Encoding utf8
$raw | Get-Member
$raw | Where-Object { $_.State -ceq 'keep' }

Импорт даёт четыре объекта со строковыми свойствами. Where-Object проверяет каждый объект; $_ обозначает текущий, -ceq сравнивает State с keep с учётом регистра. Отбор пропускает S11, S07, S02 с тремя исходными свойствами.

Числовой порядок

Что нужно изменить у строкового Units, чтобы 2 стояло перед 12? По какому полю упорядочить S02 и S11 при равных количествах 12?

$selected = $raw |
    Where-Object { $_.State -ceq 'keep' } |
    ForEach-Object {
        [pscustomobject]@{
            Code = $_.Code
            Units = [int]$_.Units
        }
    } |
    Sort-Object -Property Units, Code -Culture en-US

[int] получает целое число. Новый объект содержит два нужных свойства. Сортировка сравнивает количество, затем код: S07/2, S02/12, S11/12. -Culture en-US задаёт правила сравнения строковых кодов.

Попросить объяснить выбор дополнительного ключа для S02 и S11. Найти момент, после которого State уже отсутствует. Перед экспортом показать выбранные объекты и проверить число записей.

Текстовый отбор

В fish/Linux текущий каталог — flowlab, results уже существует. У пригодных проб S11, S07, S02 количества равны 12, 2, 12. Какие ключи сравнения поставят S07 первой, а S02 перед S11?

grep '|keep$' inputs/readings.txt |
    env LC_ALL=C sort -t '|' -k2,2n -k1,1

Обычный GNU grep выбирает строки с окончанием |keep. sort читает их из stdin. Разделитель — |. Первый ключ -k2,2n сравнивает второе поле численно. Второй ключ -k1,1 сравнивает первое поле при равенстве чисел. Локаль C задаёт порядок латинских кодов.

S07|2|keep
S02|12|keep
S11|12|keep

Соединение программ

На fish-маршруте сначала выполнить только grep и объяснить его порядок. Затем добавить сортировку. Различить вертикальную черту внутри образца в кавычках и оператор между командами.

Сохранение строк

grep '|keep$' inputs/readings.txt |
    env LC_ALL=C sort -t '|' -k2,2n -k1,1 |
    cut -d '|' -f1,2 > results/selected.txt

cut оставляет первые два поля. Перенаправление сохраняет stdout в файл, заменяя его прежнее содержимое.

S07|2
S02|12
S11|12

Проверьте файл: состав полей, последовательность записей, LF.

Прочитать результат cat. Попросить назвать вход и выход каждой стадии. Уточнить, что три стадии получили исходные данные через первую команду, а имя выходного файла относится к перенаправлению последней.

Сценарий PowerShell

В корне flowlab сохраните Select-Readings.ps1 из разобранного примера. Он получает InputPath, OutputPath, проверяет вход до записи, выполняет знакомое преобразование и задаёт код завершения.

if (-not (Test-Path -LiteralPath $InputPath -PathType Leaf)) {
    Write-Error "Входной файл не найден: $InputPath" -ErrorAction Continue
    exit 1
}

Проверка файла выполняется до конвейера. Error содержит причину, exit 1 устанавливает отказ процесса. Успешная обработка завершается через exit 0, включая пустую выборку.

В Windows используйте подготовленную разрешённую среду: действующая политика и происхождение файла проверяются перед запуском.

Открыть сохранённый исходник целиком и найти объявление двух параметров. Сопоставить тело с уже выполненным конвейером. Проверить действующую политику Windows по известному списку областей; при запрете организации перейти к разрешённой учебной среде.

Сценарий fish

В корне flowlab сохраните select.fish из разобранного примера. Его первые строки получают два аргумента:

set -l input_path $argv[1]
set -l output_path $argv[2]
if not test -f "$input_path"
    printf 'Входной файл не найден: %s\n' "$input_path" >&2
    exit 1
end

После проверки выполняются grep, sort, cut. Сценарий сохраняет $pipestatus: у grep допускает 0 или 1, у sort и cut — 0. При этих условиях весь сценарий возвращает 0.

Найти в полном исходнике сохранение статусов до следующей команды. Пройти ветвь отсутствующего файла и ветвь пустой выборки. Попросить объяснить различие кода grep и кода всего сценария.

Первый запуск

Из flowlab выполните команду выбранного маршрута:

fish

Код процесса — 0, журнал пуст. Выход содержит три пригодные записи. stdout сценария пуст: данные сохранены в файл.

Два представления

В лабораторной работе дана другая ведомость. Из одного входа требуется получить два файла: пригодные наблюдения для сравнения по количеству и исключённые наблюдения для поиска по коду.
