Интерактивная работа

Терминал принимает клавиатурный ввод и показывает вывод. Оболочка разбирает командную строку и выполняет указанную команду.

ввод → терминал → оболочка → выполнение
           ↑                    │
           └───── вывод ─────────┘

Enter передаёт строку оболочке. После завершения команды снова появляется приглашение. Стрелка вверх возвращает прежнюю команду; Tab дополняет имя. Во встроенном терминале VS Code также работает выбранная оболочка.

Политика выполнения

PowerShell 7 в Windows показывает настройки по областям:

Get-ExecutionPolicy -List
        Scope ExecutionPolicy
MachinePolicy       Undefined
   UserPolicy       Undefined
      Process       Undefined
  CurrentUser      Restricted
 LocalMachine    RemoteSigned

Undefined — настройка в области отсутствует. Действует первое заданное значение сверху: здесь CurrentUser / Restricted, сценарии запрещены. При действующей групповой MachinePolicy или UserPolicy со значением Restricted либо AllSigned остановите запуск неподписанного count.ps1; нужна разрешённая учебная среда. AllSigned требует цифровой подписи. [9]

Попросить пройти список сверху и выбрать первую заданную политику. Предложить мысленно заменить MachinePolicy на AllSigned: определить, почему настройка Process уже не разрешит неподписанный сценарий. До следующего экрана вернуть исходные значения примера и получить прогноз для добавления Process / RemoteSigned.

Разрешённый запуск сценария

В показанном состоянии MachinePolicy и UserPolicy равны Undefined. Текущий каталог — lab. Настроим сеанс и прочитаем действующую политику:

Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned
Get-ExecutionPolicy

Результат второго вызова — RemoteSigned: Process имеет приоритет над CurrentUser. RemoteSigned разрешает локальные сценарии. При другом результате снова установите старшую заданную область по Get-ExecutionPolicy -List и согласуйте среду до исполнения.

Для неподписанного файла с меткой интернет-загрузки требуется её снятие. После проверки содержимого сценария и источника загрузки:

Unblock-File -LiteralPath .\tools\count.ps1

Команда снимает метку загрузки файла. Политика сохраняется; настройка Process действует до закрытия сеанса и его дочерних процессов. [19]

Сопоставить результат Get-ExecutionPolicy с прогнозом. Попросить назвать два разных изменения: настройку сеанса и метку конкретного файла. При действующей политике организации AllSigned либо Restricted использовать разрешённую учебную среду; снять такую политику показанные команды не позволяют.

Запуск PowerShell

Текущий каталог — lab; reports/count.txt ещё отсутствует.

pwsh -NoProfile -File .\tools\count.ps1 `
  .\reports\selected.txt .\reports\count.txt
$LASTEXITCODE
Get-Content -LiteralPath .\reports\count.txt

Процесс — выполняющийся экземпляр программы. pwsh запускает отдельный процесс. -File выбирает сценарий, два следующих пути передаются ему; -NoProfile исключает загрузку профилей настройки. Обратный апостроф в конце строки продолжает команду без пробела после него.

$LASTEXITCODE хранит код последней внешней программы — здесь вызова pwsh, исполнившего count.ps1. Код 0 означает успех этого инструмента. Он выводит lines=1; чтение созданного отчёта также даёт lines=1. [8], [11]

Окружение процесса

Программа получает рабочий каталог при запуске. Собственный переход дочернего процесса в другой каталог сохраняет каталог родительской оболочки.

оболочка: lab
    └── дочерний процесс: lab → другой каталог → завершение
оболочка: lab

В истории Unix внешняя chdir после введения отдельных процессов меняла каталог только дочернего процесса, который завершался. Смена каталога стала внутренней командой оболочки, чтобы переход сохранялся для следующих команд. [20], раздел Process control

Свойства объекта

В PowerShell текущий каталог — знакомый lab.

$file = Get-Item -LiteralPath .\reports\selected.txt
$file.Name
$file.Length

Результаты обращений — selected.txt и 6: файл содержит пять букв north и один байт LF. = сохраняет результат в переменной $file.

Объект — значение определённого типа с данными и операциями. Свойство — именованная часть его данных. Точка выбирает свойство: Name хранит имя строкой, Length — размер целым числом. Тип определяет данные и операции значения. Тип объекта файла — System.IO.FileInfo. [6, сс. 61–68], [17]

Объектный конвейер

$file | Get-Member -Name Name, Length

| передаёт результат слева команде справа. Такое соединение называется конвейером. Get-Member описывает устройство полученного объекта; здесь выбраны сведения об Name и Length.

Get-Item → объект файла → Get-Member → описание свойств
            Name: строка
            Length: целое число

Обычные результаты идут через поток Success. Сообщения об ошибках идут через отдельный Error. Правая команда принимает данные из конвейера согласно своим параметрам. [10]

$raw | Where-Object { $_.State -ceq 'keep' }

Where-Object проверяет каждый объект. В блоке { ... } обозначение $_ выбирает текущий объект, .State — свойство. -ceq проверяет равенство строк с учётом регистра. Истина пропускает объект дальше.

Текущий Code State Выход
S11 keep S11
S03 skip —
S07 keep S07
S02 keep S02

Прошедшие объекты сохраняют три свойства и прежний относительный порядок. [6, сс. 99–105]

Пройти таблицу по строкам и для каждой подставить текущее State в условие. Попросить назвать свойства S07 после отбора. До сортировки сопоставить числовое и посимвольное сравнение записей 2 и 12.

Числовое свойство

$readings = $raw | ForEach-Object {
    [pscustomobject]@{
        Code = $_.Code
        Units = [int]$_.Units
        State = $_.State
    }
}

ForEach-Object выполняет блок для каждого объекта. @{ ... } связывает имена со значениями; [pscustomobject] создаёт запись с этими свойствами. [int] преобразует строку в целое число.

Теперь количество сравнивается по величине: 2 < 12. У строк '12' и '2' первыми сравниваются символы 1 и 2. Вход гарантирует корректные целые 0–999. [23, сс. 141–147]

Порядок записей

$selected = $readings |
    Where-Object { $_.State -ceq 'keep' } |
    Sort-Object -Property Units, Code -Culture en-US |
    Select-Object -Property Code, Units

Sort-Object сравнивает числовой Units, затем Code при равенстве. Порядок возрастающий. -Culture en-US задаёт правила сравнения строк; для этих кодов они дают A–Z и 0–9.

Select-Object оставляет указанные свойства. Выбор части полей называется проекцией.

Замысел Monad

В манифесте Monad 2002 года Jeffrey Snover предложил композицию инструментов администрирования через структурированные объекты. Имена свойств позволяют следующему инструменту получать нужные данные.

инструмент A → объект с именованными свойствами → инструмент B

Этот замысел объясняет происхождение объектной передачи PowerShell. Современный командлет получает тип и свойства объекта; экспорт переводит их в выбранный формат файла. Monad в 2002 году был проектом будущей среды автоматизации. [7], [22, сс. 1–5]

Строка содержит три поля: код, количество, состояние. Буквальный | разделяет поля, LF завершает строку. UTF-8 задаёт представление символов байтами.

Канал процесса Номер Назначение
stdin 0 Вход данных
stdout 1 Выход результата
stderr 2 Диагностика

Конвейер Unix

stdout программы A ── | ──→ stdin программы B

Оболочка соединяет каналы. Между программами передаются байты; получатель выделяет строки и поля по правилам формата.

В Unix pipes появились в 1972 году по предложениям Douglas McIlroy. Программы приспосабливали к чтению stdin при отсутствии файловых аргументов. Общий способ передачи позволял собирать новые последовательности из отдельных инструментов. [20], раздел Pipes

Получатель может обрабатывать поступающие записи. Сортировке нужен весь набор для окончательного порядка.

Отбор строк

grep '|keep$' inputs/readings.txt

grep выдаёт строки, соответствующие регулярному выражению — описанию текстового образца. В обычном режиме GNU grep | здесь буквален, $ обозначает конец строки. Выбираются строки с окончанием |keep.

S11|12|keep
S07|2|keep
S02|12|keep

Одинарные кавычки сохраняют образец одним аргументом. Этот | находится внутри аргумента; соединение команд записывается вне кавычек.

Сортировка полей

grep '|keep$' inputs/readings.txt |
    env LC_ALL=C sort -t '|' -k2,2n -k1,1

sort читает строки из stdin. -t '|' задаёт разделитель полей. Ключ -k2,2n выбирает второе поле и числовое сравнение; -k1,1 сравнивает коды при равных числах.

S07|2|keep
S02|12|keep
S11|12|keep

env LC_ALL=C задаёт этому запуску локаль C — правила сравнения, при которых используемые коды упорядочиваются посимвольно. [21, сс. 293–299]

Попросить связать каждый ключ с конкретной парой строк. Для 2 и 12 использовать второй столбец; для S02 и S11 — первый. Установить, какое поле теперь можно убрать из сохранённой сводки.

Проекция строки

grep '|keep$' inputs/readings.txt |
    env LC_ALL=C sort -t '|' -k2,2n -k1,1 |
    cut -d '|' -f1,2 > results/selected.txt

cut оставляет поля 1 и 2 с разделителем между ними. > записывает stdout последней команды в файл:

S07|2
S02|12
S11|12

Отбор изменил состав строк, сортировка — порядок, проекция — состав полей. [21, сс. 302–304]

Пустая выборка

Получается last=0; stages=1 0 0. $pipestatus хранит коды стадий, $status — код последней команды. У grep 1 означает отсутствие подходящих строк; sort и cut успешно обработали пустой вход.

Результат имеет 0 байт. В PowerShell пустой выход Where-Object, переданный Export-Csv, также создаёт файл нулевой длины. [3], [5]

Ошибка чтения

printf 'last=%s; stages=%s\n' "$status" "$pipestatus"

Вход отсутствует. Код cat ненулевой, sort получает пустой вход и завершается с 0. Перенаправление уже создало partial.txt.

Код читающей программы и диагностика позволяют установить причину. Проверка входа перед записью сохраняет прежнее состояние выходного пути.

Параметры сценария

В редакторе внутри flowlab создадим Select-Readings.ps1. Его начало объявляет пути и проверяет вход:

param([string]$InputPath, [string]$OutputPath)
if (-not (Test-Path -LiteralPath $InputPath -PathType Leaf)) {
    Write-Error "Входной файл не найден: $InputPath" -ErrorAction Continue
    exit 1
}

param объявляет параметры. Test-Path -PathType Leaf проверяет файл; -not обращает условие, if выполняет блок при истине. Двойные кавычки подставляют путь в сообщение.

Write-Error передаёт диагностику в Error. exit 1 отдельно задаёт код завершения. До этой проверки запись результата ещё не началась.

Попросить проследить обе ветви для существующего и отсутствующего входа. Установить, какие два значения будут меняться между вызовами. Сохранить начало файла и перейти к его продолжению на следующем экране.

Преобразование в сценарии

После проверки входа в тот же файл добавляется обработка:

Import-Csv -LiteralPath $InputPath -Encoding utf8 |
    Where-Object { $_.State -ceq 'keep' } |
    ForEach-Object {
        [pscustomobject]@{
            Code = $_.Code
            Units = [int]$_.Units
        }
    } |
    Sort-Object -Property Units, Code -Culture en-US |
    Export-Csv -LiteralPath $OutputPath -Encoding utf8NoBOM
exit 0

Новый объект сразу содержит два нужных свойства. exit 0 обозначает успех, включая пустую выборку. Корректный вход и доступный каталог результата входят в условия использования этого сценария.
