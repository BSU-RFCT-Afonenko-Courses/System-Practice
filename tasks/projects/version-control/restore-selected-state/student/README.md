# Выбор состояния для восстановления

Комплект содержит самостоятельное задание на работу с индексом Git
и рабочим файлом. Требуются Git с командой `restore`, текстовый редактор
и один выбранный маршрут: native Workspace с fish/Linux либо собственная
ОС с PowerShell 7/Windows или fish/Linux.

## Начало работы

Полное условие и открытые примеры доступны на странице задачи
«Выбор состояния для восстановления» и в скачиваемом архиве условия
`exr-version-control-restore-selected-state-conditions.zip`.
Для локального чтения распакуйте архив целиком в отдельную папку
и откройте `README.md`.

Рабочий каталог задачи — `work`:
обычный репозиторий с собственным `.git`, веткой `main` и одним начальным
коммитом. Его два файла и требуемые изменения перечислены в условии.
Для повторного опыта подходит новая копия исходного комплекта.
В собственной ОС распакуйте комплект в доступную вам папку.
Последовательность допустимых команд выбирайте самостоятельно,
пояснение создайте текстовым редактором. Имена файлов и регистр букв
сохраняйте по условию.

Откройте терминал в `work`. Проверьте текущую ветку и отсутствие
подготовленных и рабочих изменений средствами `git status`;
прочитайте `README.md` и `notes.txt` в редакторе. Для создания коммита
Git использует настроенные имя и почту автора.

## Наблюдение

`git diff` показывает различия рабочего дерева и индекса;
`git diff --staged` — индекса и текущего коммита. Наблюдения двух
восстановлений и краткое объяснение относятся к сдаче задачи.
Достаточны выбранные существенные результаты либо демонстрация на разборе.

## Сдача в native Workspace

Работайте в `work`; `explanation.md` сохраните рядом с ним.
Сохраните файлы редактора и отправьте решение штатной кнопкой PrairieLearn.
Преподаватель получает `.git`, refs, HEAD, индекс, рабочие файлы и пояснение.
При повторном открытии сохраняется выбранная работа с её промежуточными
изменениями. Вручную создавать ZIP в Workspace не требуется.

## Сдача из собственной ОС

Поместите `explanation.md` рядом с `work`. Упакуйте оба элемента
в ZIP или tar.gz способом, который включает скрытое содержимое `.git`.
Выходной архив размещается снаружи упаковываемого каталога.
После извлечения в новую папку проверьте дерево, прочитайте файлы
и историю, проверьте состояние репозитория. Способ упаковки выбирайте
самостоятельно в пределах заданного состава и формата.

Архив снимка, созданный `git archive`, содержит файлы коммита;
для этой сдачи требуется также история в `.git`. Полный комплект
позволяет преподавателю сопоставить коммиты и объяснение.

Оба маршрута сохраняют одинаковые требования к двум применениям restore.
Конечные чистые файлы и история A → B устанавливают результат; обязательные
действия и промежуточный расклад индекса/рабочего файла предъявляются
по существенным status/diff либо демонстрации и прежнему пояснению.
