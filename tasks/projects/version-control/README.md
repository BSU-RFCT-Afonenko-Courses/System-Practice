# Техническая поставка «Управления версиями»

Предметный договор задаёт каноническое условие третьей лабораторной.
`seed.json` содержит обычные файлы demo/starter; `build_git_materials.py`
упаковывает их детерминированно. Demo имеет корень latency-demo, starter —
versioning/project. Подготовленной .git, индекса, ссылок или истории в ZIP
нет. `initial-state.json` перечисляет исходные файлы и отсутствие готовой
истории; `materials-hashes.json` защищает назначения от перезаписи
неожиданных локальных поправок. Вспомогательные операции Git в модуле сохранены для
независимого добровольного проекта сопровождения.

Из корня репозитория:

```sh
python3 tools/build_git_materials.py --write
python3 tools/build_git_materials.py --check
python3 -m unittest discover -s tests -p 'test_*.py' -v
python3 tools/check_version_control.py submission.zip --output result.json
python3 tools/check_version_control.py submission.tar.gz --output result.json
```

Программа проверки предназначена для Linux-среды преподавателя с Git CLI; Python
не добавляется к требованиям студенческого маршрута. ZIP и tar.gz
распознаются по содержимому и читаются как данные без извлечения.
Пути, типы файлов, дубликаты, объём и количество записей ограничены
существующей общей поддержкой. Ссылки и особые файлы не принимаются.

Два обычных репозитория project/verification безопасно восстанавливаются
во временной области только из objects, refs, HEAD и index. Конфигурация, hooks, aliases и credential helpers сдачи не исполняются. Git globals,
подмены истории, alternates и сетевые протоколы исключены из чтения.
Remote URL наблюдаются отдельным средством разбора конфигурационных данных, который
не следует include/includeIf. SCP/ssh URL и SSH Host aliases допустимы;
направление и действительный обмен требуют внешнего наблюдения.

Автоматические наблюдения: HEAD/main и чистота обеих копий, обязательные
файлы, равенство итоговых ID, исходный A, расходящиеся B/F, двухродительский D
и включение обеих линий через его родителей. Рабочая ветка сохраняет F
либо включённое продолжение. Число учебных коммитов, identity, даты,
имя рабочей ветки и порядок родителей D не фиксируются. Дополнительные
содержательные коммиты и доброкачественные отслеживаемые файлы принимаются;
двоичные приложения не обязаны декодироваться как UTF-8. Тексты сравниваются
с допустимым LF/CRLF; measurements.tsv сохраняет исходные значения/порядок.
0.03 s и 0.030 s представляют один допустимый итоговый порог.

Смысл README/сообщений/explanation и сопоставление собственных ID остаются
в manualRequired. По графу нельзя установить саму остановку на конфликте
или единственную командную трассу. Отдельно наблюдаются индекс и применённый
приём. Remote URL и одинаковые локальные файлы не доказывают реальных
GitHub SSH push/clone. Аккаунт, ключ сервера, серверный ID, права доступа,
Windows OpenSSH/agent и оболочка принимаются по внешнему наблюдению;
секретные значения не запрашиваются.

Ресурсные пределы локального средства не являются максимумом учебной
истории. До 256 достижимых коммитов автоматическая проверка исследует
свойства и отношения; при превышении средство возвращает automated=manual,
toolLimited=true, пустые errors и отдельную diagnostics с направлением
к преподавателю. Такой результат не устанавливает нарушения договора.
Лимиты чтения архивов и ресурсов Git также дают этот исход; CLI имеет
код 2. При установленном файловом/историческом расхождении automated=fail
и код 1; успешные автоматические наблюдения дают pass и 0, сохраняя ручную
часть. Прежние потребители ArchiveError совместимы с новым подклассом
ArchiveLimit; API ZIP и безопасного Repository сохранены.

Тесты создают настоящие расходящиеся истории, локальный транспорт и обе
упаковки. Положительные варианты включают обратный порядок родителей,
нейтральный общий коммит, дополнительные файлы/коммиты, packed refs/objects,
LF/CRLF и короткую запись порога. Удалённые адреса fixtures обозначают
только тестовые строки. Linux PowerShell и GNU tar проверяются отдельно
как производители архивов, сохраняющих оба .git/index и родителей.
Успех Linux не подтверждает Windows или настоящий GitHub/SSH.
