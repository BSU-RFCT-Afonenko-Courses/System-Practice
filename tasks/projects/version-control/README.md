# Техническая поставка «Управления версиями»

Предметный договор задаёт авторское условие третьей лабораторной. `seed.json`
содержит начальные состояния двух демонстрационных и двух самостоятельных
обычных репозиториев. `build_git_materials.py` создаёт реальные objects, refs,
индекс и рабочее дерево, затем нормализует архивные метаданные и stat-поля
индекса. Синтетическая identity принадлежит исходному набору; студенческие
имена, даты и хеши новых коммитов свободны. Глобальная конфигурация не меняется.
`initial-state.json` фиксирует только исходные refs/HEAD/status;
`materials-hashes.json` защищает назначения от перезаписи локальных поправок.

Из корня репозитория:

```sh
python3 tools/build_git_materials.py --write
python3 tools/build_git_materials.py --check
python3 -m unittest discover -s tests -p 'test_*.py' -v
python3 tools/check_version_control.py submission.zip
```

Проверяющая программа предназначена для локальной Linux-среды преподавателя
с Git CLI. Она читает ZIP с ограничением размера и создаёт временный набор
данных Git. Конфигурация, hooks, внешние objects/alternates, подмены истории
и исполняемые программы сдачи не используются. Git читает только objects,
refs и индекс с отдельными ограничениями ресурсов; рабочие файлы сравниваются
отдельно, LF/CRLF допускаются. Упакованные objects и refs поддерживаются.
Отказ средства проверки требует отдельного разбора преподавателем.

Устанавливаются факты: сохранность начальных точек, родитель нового снимка,
его содержимое, индекс и сохранённая незавершённая работа; исходная точка
ветки validation, добавление checks, включение обеих линий в main и чистый
итог. Происхождение исторического файла, самостоятельность, смысл сообщений
и объяснение графа остаются в `manualRequired`. Итоговую оценку инструмент
не выставляет. Наличие локальной проверки не означает поставку Git grader,
готовность Windows или интерактивного workspace.
