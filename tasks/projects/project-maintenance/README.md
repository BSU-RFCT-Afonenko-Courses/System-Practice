# Техническая поставка сопровождения

Предметный договор принадлежит авторским страницам курса. `seed.json` задаёт
только исходные демонстрационные и самостоятельные данные; решения в них нет.
`initial-state.json` связывает исходные A/M/F, refs и входной diff-патч с ZIP.
`materials-hashes.json` фиксирует байты поставки. Все эти служебные файлы
исключены из публичного Quarto-дерева правилом `**/projects/**`.

Упаковка: `python3 tools/build_maintenance_materials.py --write` из корня курса.
Режим `--check` ничего не записывает. Неожиданная локальная правка любого
назначения останавливает всю запись этого упаковщика.

Проверка сдачи: `python3 tools/check_project_maintenance.py submission.zip`.
Она читает историю и файлы как данные через приватный Git-каталог и индекс.
Настройки и hooks студента не исполняются, сеть не используется.
`automated: pass` подтверждает перечисленные факты, а `manualRequired`
сохраняет оценку команд, смысла конфликта, пояснений и самостоятельности.
Сжатые объекты/refs, собственные identity и даты, порядок включения линий,
LF/CRLF рабочих файлов и обычные режимы 100644/100755 равноправны.

Данные эталонных решений и ошибочных сдач находятся в преподавательских tests
и отдельном локальном журнале выполнения; в исходные ZIP они не входят.

Проверяющий читает actual tag bytes и проверяет Git objects/hash/connectivity через bounded `git fsck --full --no-reflogs --no-dangling` в приватных data-only repositories. Повреждённый даже недостижимый object требует ручного разбора; такой отказ инструмента не доказывает неверность выбранной студентом истории. Config/hooks/сеть сдачи не используются. Обычный zero-context Git diff допустим: private-index apply использует `--unidiff-zero`, затем обязательно сравнивает всё полученное дерево с R.
