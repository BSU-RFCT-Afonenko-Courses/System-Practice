# Техническая поставка сопровождения

Предметный договор задают авторские страницы курса. `seed.json` описывает
исходные снимки и родителей двух независимых наборов. Demo `maintenancelab`
продолжает latency A/B/C/S/T/M/N: work/main=N, shared/main=U, поступивший
CHECKS.md и входной guide.patch по README из N. Starter `maintenance`
содержит report A/M/F и русский review.patch по A. `initial-state.json`
фиксирует созданные ID, refs, HEAD/status и hash патча; готового решения
добровольного проекта в поставке нет. Служебный каталог исключён из
публичного дерева Quarto правилом `**/projects/**`.

Из корня проекта:

```sh
python3 tools/build_maintenance_materials.py --write
python3 tools/build_maintenance_materials.py --check
python3 tools/materialize_public_materials.py --write
```

Снимки/объекты, refs, индекс и архивные метаданные детерминированы.
`--check` не записывает; повторная запись идентичного набора сохраняет mtime.
Предварительная проверка всех назначений защищает неожиданную локальную
правку от перезаписи и не оставляет частично обновлённые назначения.
Публичные demo theory/practice/handbook совпадают побайтно; общий materializer
сохраняет прежние bytes чужих наборов.

Проверка предназначена для локальной Linux-среды преподавателя с Git/Python.
Она читает всю сдачу ZIP/tar.gz как данные без извлечения путей или исполнения
программ студента. Безопасный Repository использует отдельную минимальную
конфигурацию; hooks, aliases, helpers, include, глобальная конфигурация,
замена объектов и сетевой обмен исключены. Origin и core.bare читаются
отдельно как конфигурационные данные. Переносимый origin разрешается
от work к соседнему shared.git. Bare не требует рабочего дерева или индекса.

Автоматические наблюдения: исходные теги/коммиты и входной патч; обязательные
файлы R и дополнительные обычные UTF-8 документы во вложенных каталогах;
P с непосредственным родителем A, только предусмотренным изменением текста
и прежними modes; выбранная отдельная ветка остаётся на P; M/F/P достижимы
из main через merge-связи. Свободны имя ветки, identity, сообщения, даты,
порядок родителей и число дополнительных содержательных коммитов.
Чистота индекса сравнивается по путям, байтам blob и Git modes; рабочие
тексты допускают LF/CRLF. Metadata executable bit элемента ZIP не оценивается.
Принятая поправка T1 сохраняется также после private-index применения патча.

В work/shared проверяются объекты/связность через ограниченный fsck, общий
R и тот же аннотированный tag object v2.0. Release.patch проверяется и
применяется к частному индексу start, включая весь состав и modes R.
Report-2.0.zip содержит все относительные пути и точные записанные bytes R
под report-2.0/, включая дополнительные вложенные документы. Времена,
сжатие и executable metadata ZIP свободны; явные directory entries
необязательны. Происхождение через git archive остаётся ручным наблюдением.

`automated=pass` и CLI=0 подтверждают перечисленные факты. Смысл CHANGELOG,
сообщений/аннотации, объяснения и дополнительных документов, фактические
fetch/push, конфликт, apply и git archive остаются в `manualRequired`.
Найденное файловое/историческое расхождение даёт fail и CLI=1.
При исчерпании локальных ресурсов (архивные пределы, Git timeout/output,
история свыше технического предела 256 достижимых коммитов) средство
возвращает manual, toolLimited=true, errors=[], отдельную diagnostics,
manualRequired и CLI=2. Такой исход не устанавливает нарушения учебного
договора и направляет результат на ручную проверку; учебного максимума
числа коммитов нет.

Преподавательские tests создают настоящие варианты истории и отрицательные
сдачи. Отдельные receipts наблюдают Linux PowerShell/fish demo, локальный
bare-транспорт и штатные ZIP/tar producers с последующим восстановлением.
Windows, настоящий внешний SSH, GUI редактора и публикация имеют отдельные
статусы; локальные результаты их готовности не подтверждают.
