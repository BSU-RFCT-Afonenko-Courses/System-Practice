# Техническая поставка «Рабочей среды»

Действующий предметный договор задаёт [каноническое условие](../../labs/work-environment.qmd).
Два самостоятельных комплекта находятся в `file-state/student` и
`launch-counter/student`; их состав объявлен в соответствующих
`_metadata.yml`. Задания принимаются вручную по своим условиям.
Файловый результат и наблюдение запуска счётчика предъявляются отдельно.

Общие исходники `count.fish` и `count.ps1` находятся в
`tasks/common/work-environment`. Материализация обоих проектов использует
эти файлы. `materials.json` задаёт воспроизводимые учебные ZIP для
демонстрации и исходных данных; архивы не содержат книг.

Из корня репозитория:

```sh
python3 tools/build_materials.py
python3 -m unittest discover -s tests -p 'test_*.py' -v
```

Тесты чтения ZIP и tar.gz проверяют безопасные имена, обычные типы файлов,
дубликаты, конфликты файлов с каталогами и ресурсные пределы без извлечения
студенческих данных. Эти проверки поддерживают инструменты курса и
не устанавливают выполнение самостоятельных заданий.

Сценарии `reference/` сохраняются как технические примеры подготовки
файлового результата. Тесты доверенного runtime распаковывают опубликованные
ZIP курса и запускают поставленные count в fish и PowerShell: проверяют
файлы, stdout/stderr, коды завершения и относительные пути от рабочего
каталога. Они сохраняют исходный вход и уже существующий отчёт при отказе.

PowerShell на Linux проверяется отдельно от Windows. Локальный успех
не подтверждает Windows ExecutionPolicy, VS Code, облачную среду или Moodle.
