# Техническая поставка «Рабочей среды»

Учебный контракт принадлежит [каноническому условию](../../labs/work-environment.qmd).
`materials.json` содержит данные двух ZIP, `materials-hashes.json` — результат
детерминированной упаковки. Книги в эти архивы не входят.

Из корня репозитория:

```bash
python3 tools/build_materials.py --write
python3 tools/build_materials.py --check
python3 -m unittest discover -s tests -v
python3 tools/check_work_environment.py /путь/к/результату.zip
```

Проверка читает ZIP без распаковки и исполнения. Она сравнивает исходные
и итоговые байты, набор учебных файлов внутри source/result, отсутствие work,
README и наличие читаемого пояснения. LF и CRLF разрешены в README;
исходные данные и копии сохраняются побайтно. Каталог редактора в корне
не влияет на результат. Ограничение средства чтения — 1000 записей и 8 МиБ
распакованных данных; превышение направляется на отдельную проверку.

`automated: pass` означает только совпадение доступных файловых наблюдений.
`manualRequired` всегда сохраняет содержательную приёмку пояснения и работы
в выбранной оболочке. Проверка не доказывает применение конкретной команды,
перенаправления или конвейера. История терминала не требуется.

Сценарии `reference/` создают положительный файловый fixture из свежей копии
survey; они не создают содержательного explanation.md. Полный смысл пояснения
не подменяется этими сценариями. Локальный технический probe проверяет оба
маршрута отдельно. Запуск PowerShell на Linux не подтверждает Windows,
облачную рабочую область VS Code или физическое поле сдачи в Moodle/PL.
