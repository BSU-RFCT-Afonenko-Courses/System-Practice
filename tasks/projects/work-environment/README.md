# Техническая поставка «Рабочей среды»

Учебный контракт принадлежит [каноническому условию](../../labs/work-environment.qmd).
`materials.json` содержит данные двух ZIP, `materials-hashes.json` — результат
детерминированной упаковки. Книги в эти архивы не входят.

Из корня репозитория:

```bash
python3 tools/build_materials.py --write
python3 tools/build_materials.py --check
python3 -m unittest discover -s tests -v
python3 tools/check_work_environment.py /путь/к/результату.zip
```

Проверка читает ZIP без распаковки и исполнения. Она сравнивает исходные
данные, поставленные `tools/count.ps1` и `tools/count.fish`, итоговые копии,
`result/line-count.txt` с точными байтами `lines=2\n`, отсутствие `work`
и наличие читаемого пояснения. Данные и сценарии сохраняются побайтно;
отчёт использует UTF-8 без BOM и LF. Фиксированный README больше не требуется.
Лишние учебные файлы внутри source/result выявляются отдельно. Типичные
.DS_Store и AppleDouble ._* внутри survey не считаются учебным результатом
и не заменяют обязательные файлы. Каталог редактора в корне допустим.
ZIP имеет один корень survey; безопасность имён и обычные типы файлов
проверяются независимо от игнорирования metadata. Ограничение средства
чтения — 1000 записей и 8 МиБ распакованных данных; превышение направляется
на отдельную проверку.

`materials.json` содержит текст опубликованных сценариев и исходных данных.
Два ZIP получают одинаковые count.ps1/count.fish. `expected.json` задаёт
точные итоговые файлы и перечень сохраняемых поставленных сценариев;
их байты checker берёт из исходного manifest. Новый общий runtime не нужен.

`automated: pass` означает совпадение файловых наблюдений.
`manualRequired` сохраняет смысл пояснения и отдельное наблюдение запуска
count с новым временным отчётом: CWD, аргументы, код и чтение результата;
после показа временный отчёт удаляется. Правильный lines=2 сам по себе
не доказывает запуск. Checker не исполняет submitted code, не требует
истории терминала, скриншотов или единственной последовательности команд.

Сценарии `reference/` создают положительный файловый fixture из свежей копии
survey и вызывают соответствующий поставленный count. Содержательное
explanation.md они не создают. Тесты trusted runtime распаковывают ZIP курса
и выполняют оба штатных маршрута с опубликованными данными: успех,
отсутствующий вход, существующий отчёт и отсутствующий родитель.
Относительные пути считаются от CWD вызова. Успех даёт stdout lines=N,
файл lines=N\n и код 0; объявленные отказы дают stderr и код 2.
Полного каталога форматов и ошибок договор первой работы не задаёт.

Linux-проверки PowerShell/fish имеют отдельные receipts. Запуск PowerShell
на Linux не подтверждает Windows, загрузочную метку, ExecutionPolicy,
дочерний pwsh, VS Code, облачную среду или реальный Moodle.
