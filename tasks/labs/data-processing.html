3  Обработка данных

Лаборатория хранит результаты подсчёта частиц в пробах. Проверка качества помечает пригодные наблюдения keep, исключённые — skip. Для сравнения пригодных проб нужна сводка по числу частиц; для поиска исключённых проб — отдельный список по коду. Подготовьте оба результата одним сценарием и проверьте его на двух входных наборах и отсутствующем файле.

Выберите один маршрут: PowerShell 7/Windows либо fish/Linux. Подготовка своего маршрута: объектный конвейер или текстовые потоки. Введение восстанавливает знакомое преобразование. Адресные записи команд находятся в справочнике.

3.1 Исходные наблюдения

Распакуйте стартовый архив. Его единственный корень — processing:

processing/
├── inputs/
│   ├── readings.txt
│   ├── readings.csv
│   ├── no-match.txt
│   └── no-match.csv
└── expected/
    ├── selected.txt
    ├── selected.csv
    ├── excluded.txt
    ├── excluded.csv
    ├── empty.txt
    ├── empty.csv
    ├── no-match-excluded.txt
    └── no-match-excluded.csv

Расширения представляют одинаковые наблюдения: PowerShell использует .csv, fish — .txt. Сохраните все inputs и expected без изменений. Новые учебные файлы создавайте внутри processing; сдаваемый ZIP — снаружи.

В readings записи расположены так:

Code — код пробы Units — число частиц State — решение
B03 10 keep
B01 2 keep
B06 9 skip
B02 10 keep
B05 0 keep
B04 20 skip

no-match содержит B07/1/skip и B08/11/skip в таком порядке.

Формат .txt: одна запись на строку, поля Code|Units|State, заголовка нет. Первая строка основного входа — B03|10|keep. Формат .csv: заголовок Code,Units,State, затем поля через запятую; первая запись — B03,10,keep. Входы имеют UTF-8 без BOM, окончания LF и последний LF.

Код — одна заглавная латинская буква и две цифры; коды уникальны. Количество — целое 0–999, записанное десятичными цифрами без ведущих нулей, кроме 0. Состояние — ровно keep или skip. Внутри полей нет пробелов, кавычек, разделителей и переводов строки. Это свойства всех допустимых входов. Универсальная проверка повреждённых записей в работу не входит.

Допустимо любое число записей, включая ноль. Пустой .txt имеет 0 байт; CSV без наблюдений содержит только заголовок с завершающим LF. Каждый сценарий обрабатывает формат выбранного маршрута.

3.2 Преобразование

Напишите Select-Readings.ps1 либо select.fish в корне processing. Сценарий получает путь входа и два пути результата.

Результат Отбор Порядок Поля
Пригодные наблюдения State равен keep Числовой Units по возрастанию; при равенстве Code по возрастанию Code, Units
Исключённые наблюдения State равен skip Code по возрастанию Code, Units

Для кодов действует посимвольный порядок A–Z и 0–9. Сохраняйте каждое представление в отдельном файле с указанным порядком полей. Можно повторно читать вход либо хранить прочитанные данные.

В построении каждого результата примените содержательный конвейер: соедините через | как минимум две стадии из отбора, сортировки и проекции. В fish между стадиями передаётся текст описанного формата, в PowerShell — объекты с именованными свойствами. Выберите команды и устройство сценария самостоятельно. Передача уже готового ответа только на вывод этого требования не выполняет.

Правила должны применяться к переданным данным, включая перестановки и другие корректные записи. Копирование expected или запись готового ответа в исходнике не обрабатывает входной набор.

Для readings пригодные наблюдения имеют порядок:

Code Units
B05 0
B01 2
B02 10
B03 10

Исключённые наблюдения:

Code Units
B04 20
B06 9

Для no-match первый результат пуст, второй содержит B07/1, B08/11. Образцы находятся в expected/empty.* и expected/no-match-excluded.*. Звёздочка здесь и далее означает расширение выбранного маршрута; в команду передаётся полное имя.

3.3 Формат результата

В fish непустые результаты состоят из строк Code|Units без заголовка, UTF-8 без BOM, с LF после каждой строки. Пустых строк нет. Сравнение с соответствующим expected/*.txt выполняется побайтно.

В PowerShell непустые результаты — CSV с колонками Code,Units, без #TYPE и дополнительных столбцов, UTF-8 без BOM. Допустимы LF или CRLF, корректные CSV-кавычки, наличие либо отсутствие последнего перевода строки. После разбора должны совпасть заголовок, значения и порядок записей. Units сохраняет каноническую десятичную запись. Файлы expected/*.csv показывают допустимое представление.

Любая выборка без записей сохраняется файлом ровно 0 байт в обоих маршрутах. Если вход содержит только keep, пуст второй результат; если записей нет, пусты оба файла. Повторный успешный вызов заменяет оба прежних результата.

3.4 Запуски сценария

Все вызовы выполняются из корня processing. Заранее создайте results. Аргументы передаются правильно, три пути различны, родительские каталоги выходов существуют и доступны для записи.

В PowerShell параметры называются InputPath, SelectedPath, ExcludedPath. В fish это соответственно первый, второй и третий аргументы. Используйте подготовленную среду PowerShell 7/Windows с разрешённым запуском локального сценария по правилам подготовки.

  • PowerShell 7 / Windows
  • fish / Linux
pwsh -NoProfile -File .\Select-Readings.ps1 `
    -InputPath inputs/readings.csv `
    -SelectedPath results/selected.csv -ExcludedPath results/excluded.csv `
    2> results/selected.err
$LASTEXITCODE
fish --no-config ./select.fish inputs/readings.txt results/selected.txt results/excluded.txt 2> results/selected.err
printf 'exit=%s\n' $status

Выполните три случая одним сценарием своего маршрута:

Вход Пригодные Исключённые stderr Код
inputs/readings.* results/selected.*: 4 записи results/excluded.*: 2 записи results/selected.err: пуст 0
inputs/no-match.* results/empty.*: 0 байт results/no-match-excluded.*: 2 записи results/empty.err: пуст 0
inputs/absent.* results/missing-selected.*: отсутствует results/missing-excluded.*: отсутствует results/missing.err: непуст Ненулевой

inputs/absent.txt и inputs/absent.csv отсутствуют. Перед третьим вызовом обоих missing-результатов также нет; после отказа ни один не должен появиться. Диагностика содержит имя отсутствующего входа. Язык, оформление сообщения и конкретный ненулевой код выбирайте сами.

stdout сценария пуст во всех трёх случаях: данные сохраняются в два заданных файла. Успешные вызовы оставляют stderr пустым. Ошибки неправильных аргументов, недоступного каталога и повреждённого формата лежат за объявленной областью работы.

3.5 Пояснение

Создайте explanation.md в UTF-8. Укажите среду и версию, три команды запуска и наблюдённые коды. Объясните данные между стадиями обоих конвейеров: поля строки либо свойства и типы объекта, количество записей для основного входа. Обоснуйте числовой порядок 2 и 10, порядок равных количеств, порядок исключённых проб B04 и B06.

Сопоставьте пустую выборку с ошибкой входа, укажите место диагностики. Опишите сравнение с expected, включая порядок записей и кодировку.

3.6 Сдача

Предъявите ZIP с единственным корнем processing, исходными inputs и expected, выбранным сценарием, explanation.md, результатами своего маршрута. В results находятся четыре файла данных: selected.*, excluded.*, empty.*, no-match-excluded.*; три журнала: selected.err, empty.err, missing.err. Файлов missing-selected.* и missing-excluded.* нет. Служебные файлы редактора не входят в учебный результат.

Файловая проверка устанавливает данные, порядок, сохранность входов, пустую выборку и диагностику. Применение двух конвейеров проверяется по исходнику и разбору работы. На разборе выполните сценарий на согласованной перестановке либо другом допустимом наборе и объясните данные на выбранной границе стадий.
