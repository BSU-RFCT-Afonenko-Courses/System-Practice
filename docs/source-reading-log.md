Уточнения к переносу книги:

- Снимок — семантическая модель; упаковка объектов может использовать дельты.
- Обычный clone получает историю, доступную при выбранных параметрах;
  shallow/partial clone исключают универсальное утверждение о любой копии.
- Современный Git поддерживает SHA-1 и SHA-256; ветка не определяется
  универсально как отдельный файл фиксированной длины.
- Источник обычного `restore` — индекс; у `restore --staged` по умолчанию HEAD.
- Fast-forward определяется достижимостью по родителям; прямое родительство
  для него не требуется.
- `origin/main` хранит локально полученное значение. После чужого push оно
  может отставать до следующего обмена.
- Исторические указания об HTTPS-пароле аккаунта GitHub требуют замены
  современным описанием GCM/браузерного входа.

Контрольные границы: первый `init` создаёт ещё не родившуюся ветку;
`add` фиксирует текущее содержимое для следующего обычного commit;
`commit -a` не добавляет новые неотслеживаемые файлы; `switch` может сохранять
совместимые незакоммиченные изменения, а потеря содержимого блокируется;
основные опыты начинаются с чистого состояния, чтобы видно было одно действие.
`merge --ff-only` допускает также уже включённую историю; расходящиеся вершины
требуют иного способа интеграции. Разрешение конфликта завершается подготовкой
выбранного содержимого и обычным commit либо merge --continue.

### Содержательные уточнения источников

1. Shotts использует Bash. Общая модель путей и потоков полезна для курса;
   синтаксис группировки и подстановок переносится в fish только после
   отдельной сверки. Совет избегать пробелов в именах не становится
   ограничением заданий: курс учит корректной передаче такого имени.
2. Вводная книга Jones предлагает аналогию большой таблицы в памяти.
   Она помогает различить объект и свойство, однако не принимается
   как модель обязательного накопления всего конвейера. Прочитанная
   документация PowerShell уточняет поэлементную передачу.
3. Разбор `Get-Member` помогает явно устанавливать свойства данных
   между стадиями. Выбор и форматирование имеют собственные результаты;
   схема курса показывает эти переходы. Процессы и службы из книжного
   опыта заменяются авторскими локальными данными.
4. В русском учебнике на с. 143 утверждение о невозможности перенаправления
   вывода `Write-Host`, а на с. 147 описание автоматического возврата объекта
   из `Add-Member` требуют адресного уточнения перед соответствующей темой.
   Они не используются как нормы нового курса. Образец создаёт данные
   через `[pscustomobject]`; тема дополнительных потоков оставлена для
   следующего чтения и проверки документации.
5. В Pro Git выбираются определения снимка и индекса и опыт повторного
   редактирования. Риторика превосходства инструмента, гарантии полной
   неуязвимости данных и буквальная универсализация SHA-1 не переносятся.
   Рабочее состояние, индекс и HEAD показываются раздельно. Имя основной
   ветки задаётся учебным репозиторием.
6. Мотивы создания Git упомянуты книгой, но самостоятельный исторический
   рассказ в первом наборе не написан. Для него потребуется первичный
   источник именно мотива; чтение учебника не выдаётся за такое свидетельство.

### Авторские решения после чтения

Композиция первой темы: терминал и оболочка → аргументы → рабочий каталог
и путь → чтение, копирование и перемещение → справка → буквальные имена
и шаблоны → диагностика. Один малый каталог `lab` даёт видимые состояния
и сохраняется в теории, лекции и вводном разборе. Самостоятельный `survey`
имеет другие данные и два связанных требования к файловому результату.
Пример из книги не воспроизводится: системный `/etc/passwd`, процессы,
реестр и службы заменены собственными статическими наблюдениями.

Ссылки и рекурсивное удаление не стали скрытыми требованиями первой
лабораторной. Удаляется один известный временный файл и пустой каталог.
Справочник показывает условия операции и её наблюдаемый результат.
Обязательное объяснение одного параметра соединяет чтение справки
с собственным решением, не навязывая единственную последовательность команд.

Уточнения источников:

- Совет Jones запускать PowerShell администратором относится к старому
  административному курсу; файлы новой лабораторной находятся в собственном
  каталоге и не требуют повышения прав.
- Утверждение Jones о запуске внешних команд через Cmd.exe, пример
  назначения `$host`, устаревшие инструкции ISE и обобщения про параметры
  не перенесены в современную тему. Совпадение коротких имён разных
  оболочек не используется как основание равенства их семантики.
- Описание ASCII у Shotts не обобщается до «символ всегда равен байту»:
  теория отдельно называет кодировку и переменную длину UTF-8.
- Шаблоны Bash из TLCL не выдаются за полный синтаксис fish.
  Ввод ограничен `*`; пример буквального пути PowerShell использует
  `-LiteralPath`, а пример шаблона — `-Path`.

### Решение о пяти формах и самостоятельном переносе

Теория связывает получение истории, конфликт, проверку патча, тег,

самостоятельное условие. Студент выбирает базу и порядок объединения трёх
линий, обосновывает состав другого отчёта, передаёт историю и проверяет
связь тега, патча и архива с итоговым снимком. Три обязательные лабораторные
сохраняются. Факты о сдаче и ручная проверка применённых приёмов разделены.
