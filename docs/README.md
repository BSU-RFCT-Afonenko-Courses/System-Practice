# Работа над курсом System Practice

Принятая предметная редакция курса охватывает пять учебных
форм и ровно две лекции: «Командный интерфейс» и «Управление версиями».
Студенты входят в командную среду через знакомые файлы и каталоги.
Основные демонстрации используют PowerShell 7/Windows; fish/Linux имеет
полный практический маршрут. GitHub и SSH входят в обязательную третью
лабораторную. Три лабораторные и добровольный проект сохраняют небольшой
объём самостоятельной работы.

## Действующая программа 7 ноября

Объём и окно исполнения определяют [единая спецификация](https://github.com/BSU-RFCT-Afonenko-Courses/Java/blob/d8647f9b9509d9a78ac483717b1b852f574bae5d/docs/superpowers/specs/2026-11-07-java-system-practice-night-design.md)
и [план](https://github.com/BSU-RFCT-Afonenko-Courses/Java/blob/d8647f9b9509d9a78ac483717b1b852f574bae5d/docs/superpowers/plans/2026-11-07-java-system-practice-night.md).
Актуальный банк SP содержит семь задач и пять работ; сохраняются оба
маршрута bundle/Workspace. Состав банка не выводится из исторических
26 карточек или прежних четырёх архивов.

[Матрица ролей](https://github.com/BSU-RFCT-Afonenko-Courses/Java/blob/d8647f9b9509d9a78ac483717b1b852f574bae5d/docs/agent-execution-proposal-20261029.md) — единый норматив моделей
и усилий; разрешены только `gpt-6.1-sol` и `gpt-6.1-terra` с явным effort.

Предметные правила находятся в [методике](authoring-methodology.md#публикация-банка-заданий),
включая [студенческое представление PrairieLearn](authoring-methodology.md#представление-задачи-в-prairielearn).

## Работа и приёмка

Координатор фиксирует исходный SHA, владельцев, модельные интервалы
и отчёты в рабочей области текущего запуска. Старые машинные пути,
ветки, START и очереди не являются поручением. Пользовательские деревья,
изменения и открытые PR сохраняются; приватные журналы и книги
в репозиторий не переносятся.

Учебный автор Sol/high передаёт цели, файлы, точный снимок, фактическое
чтение, допустимые решения и ограничения. Другой Sol/high независимо
принимает содержание и стиль каждой изменённой смысловой дельты. Код
пишет технический исполнитель по матрице. Принятые единицы сохраняют
статус с учётом последующих замечаний; нового общего пилота нет.

Техническая приёмка связывает source SHA, зависимости, render и фактически
просмотренную выдачу. Статусы source, render, export, runtime и сервера
различаются. Windows/PowerShell, fish/Linux и GitHub по SSH имеют собственные
свидетельства; локальная имитация remote подтверждает механизм обмена.
По [решению 79](https://github.com/BSU-RFCT-Afonenko-Courses/Java/blob/d8647f9b9509d9a78ac483717b1b852f574bae5d/docs/refactoring-plan.md#decision-79) обязательного перехода SP
из Moodle нет. Недоступная эксплуатационная проверка остаётся отдельной.

## История редакций

Редакция от 16 октября начиналась на
`fb2681e4847c85bea0c98c6fcfad7a442d1ff017` и сохраняется в истории Git.
Её управляющий комплект r3 и волны S0–S6 имеют историческое значение.
Полная прежняя запись состояния доступна командой
`git show 97339ca2e61e9a3fbd0da6735cd7fb1554eefffd:docs/README.md`.
В ней перечислены принятые снимки методики, командной среды, обработки
данных, Git и сопровождения; свидетельства относятся к названным снимкам.
Журнал чтения сохраняет прежние страницы и вклад с явной датой этапа.

[Архив README](https://github.com/BSU-RFCT-Afonenko-Courses/System-Practice/blob/d254c636bbc0701e881315802dc3a3f775b7d872/docs/history/README.md), старые карточки и `provenance/`
описывают первую поставку. Старые `_cards/topics/pages` и
`provenance/id-map.json` описывают прежний состав и не задают активный договор;
учебные файлы и `id-map` сохраняются. [UPSTREAM](../UPSTREAM.md) хранит происхождение
технических компонентов. Ветка `reference/pr-1-c712a0b` содержит технический
пилот PrairieLearn. Прежние 26 карточек, внутренние ID и расписания
не задают новую композицию. Реальные внешние входы курса и работающие
интеграции сохраняются; их состояние проверяется отдельно.

## Внешние действия

Полномочия на PR, merge и публикацию определяет действующий регламент;
выполнение координирует интегратор после независимой приёмки. Сервер,
Moodle, сертификаты, аккаунты и личные ключи в текущую ночь не изменяются.
Пользовательские и студенческие данные сохраняются. Учебная инструкция
о регистрации GitHub не разрешает создавать аккаунт или менять ключи
пользователя. Недоступность внешней проверки фиксируется в отчёте.
