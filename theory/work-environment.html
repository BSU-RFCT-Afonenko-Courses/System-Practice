2  Рабочая среда

Файлы. Командная строка. Рабочий каталог. Файловые операции. Справка. Запуск программы.

2.1 Чтение файла

Файловый менеджер показывает содержимое выбранного каталога. Чтобы открыть текст, пользователь выбирает файл по его положению в дереве. В наборе для разбора каталог lab содержит файл input/room A.txt со строкой north:

lab/
└── input/
    └── room A.txt → north

Распакуйте набор в собственную рабочую папку. В примерах Windows это C:\course\lab, в Linux — /home/student/lab; при выполнении используется фактическое место распаковки. Откройте room A.txt текстовым редактором: внутри находится слово north и перевод строки.

Тот же файл можно прочитать командой. Терминал предоставляет окно для ввода команд и просмотра вывода. В нём работает оболочка — программа, которая разбирает командную строку и выполняет указанную операцию. Основные демонстрации используют PowerShell 7 в Windows. Для Linux приведён маршрут fish; работу достаточно выполнять в одном маршруте.

Текущий каталог PowerShell — C:\course\lab. Команда чтения:

Get-Content -LiteralPath '.\input\room A.txt'

Результат в терминале:

north

Команда указывает выполняемую операцию. Аргументы передают ей данные и выбирают режим. В записи выше Get-Content — имя команды чтения текста; -LiteralPath — имя параметра, которому передан путь .\input\room A.txt. Начальная точка выбирает текущий каталог, затем путь проходит через input к файлу. Параметр принимает буквальные имена без раскрытия файловых шаблонов. Get-Content относится к командлетам — командам, реализованным для среды PowerShell. Имена командлетов имеют форму «глагол-существительное». [5, сс. 16–21]

Одинарные кавычки сохраняют пробел внутри одного строкового значения. Сами кавычки в имя файла не входят. В fish из каталога /home/student/lab чтение записывается так:

cat './input/room A.txt'

Внешняя программа cat получает один аргумент ./input/room A.txt и выводит north. Без кавычек запись cat ./input/room A.txt передала бы два аргумента: ./input/room и A.txt. Программа попыталась бы открыть два других файла. В одинарных кавычках обеих оболочек текст этих путей сохраняется буквально. [4], [10]

2.2 Интерактивная оболочка

Оболочка показывает приглашение перед вводом очередной команды. В нём могут быть видны имя пользователя и текущий каталог. Нажатие Enter передаёт законченную строку оболочке. После завершения команды приглашение появляется снова. Стрелка вверх возвращает прежнюю команду для изменения; Tab помогает дополнить имя. В блоках курса записаны команды без приглашения.

ввод пользователя → терминал → оболочка → выполнение команды
                          ↑                  │
                          └── вывод ─────────┘

Терминал может быть отдельным приложением или панелью VS Code. Во встроенном терминале также запускается конкретная оболочка. Открытая папка редактора и текущий каталог уже работающей оболочки могут различаться: каждый из них меняется своим действием.

В Windows установленную PowerShell 7 запускает pwsh или профиль PowerShell 7 в терминале. Windows PowerShell 5.1 запускается отдельно. В Linux установленная fish запускается командой fish. Выбранную среду проверяют по версии:

  • PowerShell 7 / Windows
  • fish / Linux
$PSVersionTable.PSVersion

Переменная $PSVersionTable предоставлена PowerShell; поле PSVersion содержит версию оболочки. Здесь требуется основная версия 7.

fish --version

Команда выводит имя оболочки и её версию.

Установку PowerShell описывает официальная инструкция для Windows. [13] Рабочая папка должна быть доступна обычному пользователю на запись. Файловые команды выполняют операции с правами этого пользователя.

Интерактивная работа сформировалась вокруг короткого цикла обращения к машине и наблюдения результата. В статье о CTSS 1962 года Корбато, Мервин-Даггетт и Дейли описывали задержки пакетной обработки: программист мог ждать результата очередной проверки часами. Разделение времени предоставляло нескольким пользователям доступ через консоли; система поочерёдно выделяла процессор их работе. Это позволяло продолжать отладку после очередного ответа. [1, сс. 335–336]

2.3 Рабочий каталог

Каталог содержит имена вложенных файлов и каталогов. Путь задаёт их последовательность и конечное имя. Рабочий каталог оболочки служит началом отсчёта относительного пути. Два файла из набора имеют одинаковое конечное имя и разное содержимое:

lab/
├── input/
│   └── room A.txt → north
└── reports/
    └── input/
        └── room A.txt → south

Каждый файл содержит указанное слово с переводом строки. В учебном дереве используются обычные файлы и каталоги без символических ссылок.

Абсолютный путь включает корень и полностью задаёт расположение. В Windows это C:\course\lab\input\room A.txt, в Linux — /home/student/lab/input/room A.txt. Относительный путь начинается в рабочем каталоге. Компонент . обозначает текущий каталог, .. — родительский. Разделитель компонентов в примерах Windows — \, в Linux — /. [18, сс. 7–12]

Выбор исходного каталога и проверка пути:

  • PowerShell 7 / Windows
  • fish / Linux
Set-Location -LiteralPath 'C:\course\lab'
Get-Location
Get-Content -LiteralPath '.\input\room A.txt'

Set-Location выбирает каталог; Get-Location показывает его в поле Path. Чтение выводит north. Полный путь на другом компьютере нужно заменить фактическим. Запись C:lab зависит от текущего расположения на диске C:; полный путь C:\lab начинается в корне диска. [14]

cd '/home/student/lab'
pwd
cat './input/room A.txt'

cd выбирает рабочий каталог; pwd показывает его абсолютный путь. Чтение выводит north. Путь домашней папки заменяют фактическим.

Перейдём во вложенный reports, затем повторим чтение:

  • PowerShell 7 / Windows
  • fish / Linux
Set-Location -LiteralPath '.\reports'
Get-Content -LiteralPath '.\input\room A.txt'
Get-Content -LiteralPath '..\input\room A.txt'
cd reports
cat './input/room A.txt'
cat '../input/room A.txt'

Первое чтение выводит south: путь начинается в lab/reports. Второе выводит north: .. поднимается к lab, затем выбираются его input и room A.txt.

lab/reports → input → room A.txt             south
lab/reports → .. → lab → input → room A.txt   north

Содержимое обоих файлов сохранилось. Изменение рабочего каталога изменило начало относительного пути. Абсолютный путь к первоначальному файлу продолжает выбирать его из обоих каталогов.

2.4 Состояние файлов

Просмотр каталога сообщает имена элементов. Чтение сообщает данные файла. Текстовый редактор изменяет его содержимое после сохранения. Файл хранит байты; кодировка задаёт представление символов этими байтами. Учебные тексты используют UTF-8. Несохранённое изменение вкладки ещё не записано в файл, который читает команда.

Вернёмся из reports в lab. Создадим каталог work для копии северного наблюдения. Каталога work в исходном наборе нет; после его создания текущим каталогом оболочки остаётся lab.

  • PowerShell 7 / Windows
  • fish / Linux
Set-Location -LiteralPath ..
New-Item -ItemType Directory -Path work
Copy-Item -LiteralPath '.\input\room A.txt' -Destination work\selected.txt
Get-ChildItem -LiteralPath work
Get-Content -LiteralPath work\selected.txt

New-Item создаёт элемент; -ItemType Directory выбирает каталог. Copy-Item получает источник в -LiteralPath и назначение в -Destination. Get-ChildItem показывает имена внутри work.

cd ..
mkdir work
cp './input/room A.txt' work/selected.txt
ls work
cat work/selected.txt

mkdir создаёт каталог. cp получает источник первым аргументом, назначение — вторым. ls показывает имена внутри work.

Копирование сохраняет исходный файл и создаёт файл по новому пути. Оба файла содержат north. Имя selected.txt взято из последнего компонента назначения; родительский work создан заранее. Байты копии совпадают с байтами источника. [11], [18, сс. 29–31]

Переместим копию в существующий reports. Пути reports/selected.txt до операции нет:

  • PowerShell 7 / Windows
  • fish / Linux
Move-Item -LiteralPath work\selected.txt -Destination reports\selected.txt
Get-ChildItem -LiteralPath work -Force
Remove-Item -LiteralPath work
Get-Content -LiteralPath reports\selected.txt
mv work/selected.txt reports/selected.txt
ls -a work
rmdir work
cat reports/selected.txt

После перемещения старый путь work/selected.txt отсутствует, reports/selected.txt содержит north. В work нет вложенных элементов; в выводе ls -a записи . и .. обозначают сам каталог и его родителя. Пустой work удаляется. Для обычного файла команда удаления в PowerShell — Remove-Item, в fish/Linux — внешняя программа rm; rmdir удаляет пустой каталог. Эти операции не отправляют файл в корзину менеджера. [16], [18, сс. 31–34]

Существующее назначение требует отдельного решения. Каталог назначения может принять файл под его прежним именем; существующий файл может быть заменён либо вызвать отказ согласно правилам команды. Перед операцией проверяют точный путь назначения. В разобранной последовательности все новые файлы назначения первоначально отсутствовали.

2.5 Справка

Нужно увидеть также файлы внутри reports/input. Рекурсивный просмотр обходит вложенные каталоги. Режим обхода описан в справке команды.

  • PowerShell 7 / Windows
  • fish / Linux
Get-Command Get-ChildItem
Get-Help Get-ChildItem -Parameter Recurse
Get-Help Get-ChildItem -Examples

Get-Command устанавливает доступную команду. Get-Help показывает описание параметра или примеры. Параметр-переключатель -Recurse включает обход вложенных каталогов:

Get-ChildItem -LiteralPath reports -Recurse

Если локальные файлы справки отсутствуют, доступна онлайн-версия:

Get-Help Get-ChildItem -Online
type ls
ls --help
man ls

type устанавливает, что запускается по имени. Имя в fish может обозначать функцию, встроенную команду или внешнюю программу. Справка GNU ls описывает параметр -R, также записываемый --recursive:

ls -R reports

В просмотрщике man клавиша q возвращает в оболочку. Команда help открывает документацию самой fish.

Обозначения справки описывают форму записи. Например, <String> означает место строкового значения; в выполняемой команде там будет конкретный путь. Квадратные скобки часто обозначают необязательную часть синтаксиса. Точное значение, обязательность и допустимые значения параметра указаны в его описании. [5, сс. 23–36], [12]

2.6 Файловый шаблон

Шаблон выбирает имена по образцу. В PowerShell поддержка шаблона зависит от параметра. Из lab команда Get-ChildItem -Path '.\input\*.txt' выбирает подходящие имена в input. Кавычки сохраняют строковое значение; -Path интерпретирует звёздочку. Параметр -LiteralPath использует буквальное имя.

В fish ls input/*.txt раскрывает незаключённую в кавычки звёздочку в существующие имена до запуска ls. В пределах одного компонента * соответствует последовательности символов; имена с начальной точкой этот образец не выбирает. cat 'input/*.txt' получает буквальный аргумент со звёздочкой и ищет такое имя. Если совпадений для незаключённого шаблона нет, fish сообщает об этом и не запускает ls. [3], [11]

2.7 Программный проект

В том же lab поставлены исходники небольшого инструмента подсчёта строк:

lab/
├── tools/
│   ├── count.ps1
│   └── count.fish
├── input/room A.txt          north
└── reports/
    ├── input/room A.txt      south
    └── selected.txt          north

Программный проект объединяет исходный текст программы, входные данные и создаваемые результаты. count.ps1 записан для PowerShell, count.fish — для fish. Оба варианта выполняют одну операцию. Их исходники можно открыть текстовым редактором; для опыта используется готовый вариант своей оболочки.

Сценарий — файл команд для исполнения оболочкой. Инструмент получает два пути: сначала входной текст, затем новый файл отчёта. Он считает строки, создаёт отчёт lines=N и выводит эту же строку в терминал. Здесь все строки входных файлов заканчиваются переводом строки; завершающий перевод строки закрывает последнюю строку текста. В selected.txt одна строка north, поэтому ожидается lines=1. Каталог отчёта должен существовать, сам файл отчёта перед запуском должен отсутствовать.

Процесс — выполняющийся экземпляр программы. Для исполнения сценария ниже запускается отдельный процесс выбранной оболочки.

Для PowerShell в Windows условия запуска сценария задаёт политика выполнения. Из lab посмотрите значения по областям действия:

Get-ExecutionPolicy -List

Например, команда показывает:

        Scope ExecutionPolicy
MachinePolicy       Undefined
   UserPolicy       Undefined
      Process       Undefined
  CurrentUser      Restricted
 LocalMachine    RemoteSigned

Undefined означает, что значение в этой области не задано. Области перечислены по убыванию приоритета: MachinePolicy, UserPolicy, Process, CurrentUser, LocalMachine. Действует первое заданное значение. В примере это Restricted из CurrentUser; запуск сценариев запрещён.

MachinePolicy и UserPolicy задаются групповой политикой организации. Если действующее значение взято из одной из этих областей и равно Restricted, сценарии запускать нельзя. Значение AllSigned требует цифровой подписи, которой у учебного count.ps1 нет. В этих случаях остановите запуск и используйте разрешённую преподавателем учебную среду. Настройка Process и снятие метки загрузки такой запрет не изменяют.

В показанном примере обе групповые политики не заданы. Разрешим локальные сценарии для текущего сеанса и прочитаем фактически действующее значение:

Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned
Get-ExecutionPolicy

Результат второго вызова — RemoteSigned: теперь заданная область Process имеет приоритет над CurrentUser. Действие настройки ограничено текущим сеансом и его дочерними процессами. Если наблюдается другое значение, повторите Get-ExecutionPolicy -List, установите определяющую область и согласуйте разрешённую среду до запуска.

При RemoteSigned неподписанный файл с меткой интернет-загрузки требует снятия этой метки. Прочитайте сценарий из полученного набора курса, проверьте источник загрузки, затем примените к этому файлу из lab:

Unblock-File -LiteralPath .\tools\count.ps1

Команда снимает метку загрузки с выбранного файла; действующая политика выполнения сохраняется. [8], [15]

Запуск из рабочего каталога lab, где reports/count.txt ещё отсутствует:

  • PowerShell 7 / Windows
  • fish / Linux
pwsh -NoProfile -File .\tools\count.ps1 `
  .\reports\selected.txt .\reports\count.txt
$LASTEXITCODE
Get-Content -LiteralPath .\reports\count.txt

pwsh запускает отдельный процесс PowerShell. -NoProfile исключает загрузку профилей — файлов предварительной настройки PowerShell; -File задаёт исполняемый сценарий. Два следующих пути передаются сценарию. Обратный апостроф в конце первой строки продолжает команду; после него нет пробела. $LASTEXITCODE показывает код завершения последней внешней программы. [6], [9]

fish --no-config tools/count.fish reports/selected.txt reports/count.txt
echo $status
cat reports/count.txt

fish запускает отдельный процесс оболочки и исполняет указанный файл. --no-config исключает загрузку файлов настройки fish. Следующие два аргумента получают роли входа и отчёта. echo $status сразу после вызова показывает код завершения этой команды. [2], [4]

Инструмент выводит lines=1, код завершения равен 0; чтение созданного отчёта снова даёт lines=1. Исходный reports/selected.txt сохраняется. Код 0 здесь сообщает об успешном выполнении инструмента; значения остальных кодов определяет его договор.

2.8 Отказ программы

В lab/input отсутствует missing.txt. Передадим этот путь инструменту; выходной reports/missing-count.txt также отсутствует:

  • PowerShell 7 / Windows
  • fish / Linux
pwsh -NoProfile -File .\tools\count.ps1 `
  .\input\missing.txt .\reports\missing-count.txt
$LASTEXITCODE
fish --no-config tools/count.fish input/missing.txt reports/missing-count.txt
echo $status

Инструмент сообщает, что входной файл не найден, возвращает код 2 и не создаёт отчёт. Ранее полученный reports/count.txt остаётся прежним. Причина относится к входному пути: проверка текущего каталога и списка input устанавливает отсутствие файла. Отказ в доступе имел бы другую причину — права пользователя на конкретную операцию.

2.9 Поиск программы

Имя внешней программы, например pwsh или fish, оболочка ищет среди доступных команд и в каталогах переменной окружения PATH. PATH хранит список каталогов для этого поиска. Get-Command pwsh в PowerShell и type fish в fish показывают найденную команду. Для исходника сценария в примере задан явный путь из lab. Смена вкладки редактора не изменяет этот путь. [4], [7]

2.10 Рабочий каталог процесса

Отдельный процесс получает рабочее окружение при запуске. Его собственный переход в другой каталог не меняет каталог родительской оболочки. Ритчи описывает эту границу в истории Unix: после введения отдельных процессов для команд внешняя chdir меняла каталог дочернего процесса, который затем завершался. Для сохранения перехода в оболочке операция смены каталога стала её внутренней командой. [17], раздел Process control

2.11 Результат выполнения
