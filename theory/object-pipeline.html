4  Объектный конвейер

Объекты PowerShell. Импорт CSV. Отбор, сортировка, проекция. Сериализация. Экранное представление. Замысел Monad. Диагностика команды. Параметры сценария. Область выполнения. Функции. Сопоставление результатов.

Список файлов, ведомость наблюдений и результат расчёта состоят из значений, которые можно передать следующей команде. PowerShell сохраняет у передаваемого значения его тип и доступные свойства. Команды отбора, сортировки и записи используют эти сведения для своего действия.

4.1 Свойства объекта

В знакомом каталоге lab файл reports/selected.txt содержит north с завершающим LF. Получим сведения об этом файле в PowerShell 7:

$file = Get-Item -LiteralPath .\reports\selected.txt
$file.Name
$file.Length

Два обращения к свойствам дают selected.txt и 6. Шесть байтов — пять латинских букв в UTF-8 и один байт перевода строки LF. Get-Item возвращает объект файла типа System.IO.FileInfo. Переменная $file хранит полученное значение; = выполняет присваивание. Точка в $file.Name выбирает свойство по имени. [9]

Объект — значение определённого типа, у которого доступны данные и операции. Свойство — именованная часть доступных данных объекта. Метод — операция, которую можно вызвать у объекта. Тип определяет устройство значения и допустимые операции. Строка хранит последовательность символов, целое число участвует в арифметике и числовом сравнении. У объекта файла Name имеет строковое значение, Length — целочисленное. [1, сс. 61–68]

Для исследования объекта служит Get-Member:

$file | Get-Member

Знак | образует конвейер: результат команды или выражения слева передаётся команде справа. Get-Member принимает объект и описывает его тип, свойства и методы. Видимая в терминале таблица — представление этих сведений. Передаваемый объект сохраняет данные, доступные по именам. [5], [10]

4.2 Ведомость наблюдений

Лаборатория считает частицы в пробах. В ведомость записаны код пробы, число частиц и решение проверки качества. Значение keep допускает наблюдение в сводку; skip исключает его. Для сравнения пригодных наблюдений нужна сводка по возрастанию числа частиц. При равенстве чисел порядок задаётся кодом пробы.

Распакуйте демонстрационный набор и откройте полученный каталог flowlab в терминале. Для нового выполнения используйте свежую распаковку. Входы и образцы результата находятся в inputs и expected; каталог results создаётся для ваших выходных файлов. Все следующие относительные пути отсчитываются от flowlab.

New-Item -ItemType Directory -Path results
Get-Content -LiteralPath inputs/readings.csv
Code,Units,State
S11,12,keep
S03,4,skip
S07,2,keep
S02,12,keep

CSV — текстовый формат таблицы с разделителем полей и правилами кавычек. Здесь разделителем служит запятая, первая строка задаёт имена столбцов. Code — код пробы, Units — число частиц, State — решение проверки. В этих данных внутри полей нет запятых, кавычек, пробелов и переводов строки. Коды уникальны: заглавная латинская буква и две цифры. Числа — целые от 0 до 999 без ведущих нулей, кроме самого 0. Файл имеет кодировку UTF-8 без BOM и окончания строк LF.

$raw = Import-Csv -LiteralPath inputs/readings.csv -Encoding utf8
$raw | Get-Member

Import-Csv создаёт по объекту на запись. Имена свойств берутся из заголовка; значения свойств получаются строками. $raw хранит четыре объекта. В описаниях Code, Units, State у Get-Member указан строковый тип. Запись цифрами 12 в файле сама по себе не назначает свойству целочисленный тип. [11]

4.3 Отбор объектов

При передаче $raw через конвейер PowerShell перечисляет четыре объекта коллекции по одному. Команда справа должна поддерживать такой вход; это свойство её параметров описано в справке. [5]

$raw | Where-Object { $_.State -ceq 'keep' }

Where-Object проверяет условие для каждого полученного объекта. Фигурные скобки задают блок сценария — фрагмент выражений и команд. В этом блоке $_ обозначает текущий объект; .State выбирает его свойство. Оператор -ceq проверяет равенство строк с учётом регистра. Для данного скалярного свойства результат сравнения — истина или ложь. Истина пропускает объект дальше, ложь исключает его. [1, сс. 99–105]

Code State Условие Выход отбора
S11 keep Истина S11
S03 skip Ложь —
S07 keep Истина S07
S02 keep Истина S02

У трёх прошедших объектов сохраняются все исходные свойства. Отбор изменяет состав записей, сохраняя их относительный порядок.

4.4 Числовое значение

Для сравнения количества частиц преобразуем Units в целое число:

$readings = $raw | ForEach-Object {
    [pscustomobject]@{
        Code = $_.Code
        Units = [int]$_.Units
        State = $_.State
    }
}
$readings | Get-Member

ForEach-Object исполняет блок для каждого объекта. Запись @{ ... } связывает имена со значениями; [pscustomobject] создаёт объект с такими свойствами. [int] преобразует десятичную строку в целое число. Созданный объект становится результатом блока. В каждом выполнении блока здесь получается одна новая запись. [14, сс. 141–147]

Тип Units теперь обозначен как int. Числа сравниваются по величине: 2 < 12. При посимвольном сравнении строк '12' и '2' первыми сравниваются символы 1 и 2, поэтому порядок этих двух записей иной. Преобразование опирается на заданную область корректных целых чисел.

4.5 Порядок записей

$selected = $readings |
    Where-Object { $_.State -ceq 'keep' } |
    Sort-Object -Property Units, Code -Culture en-US |
    Select-Object -Property Code, Units
$selected

Sort-Object сначала сравнивает Units, при равенстве — Code. По умолчанию порядок возрастающий. -Culture en-US задаёт правила строкового сравнения; для этих кодов получается порядок букв A–Z и цифр 0–9. S02 и S11 имеют одинаковое количество частиц, поэтому их относительный порядок определяется кодом. [12]

Select-Object -Property Code, Units создаёт записи с двумя указанными свойствами. Выбор части полей называется проекцией. Свойство State уже использовано при отборе и в готовой сводке отсутствует.

Code Units
---- -----
S07      2
S02     12
S11     12

Между первыми стадиями передаются объекты с тремя свойствами; после проекции — с двумя. Поэлементный отбор может выдавать результат по мере чтения. Для окончательной сортировки Sort-Object сначала получает весь набор.

4.6 Сохранение CSV

Сериализация переводит данные в формат хранения или передачи. Export-Csv записывает имена и значения свойств в текстовый файл:

$selected | Export-Csv -LiteralPath results/selected.csv -Encoding utf8NoBOM
Get-Content -LiteralPath results/selected.csv
"Code","Units"
"S07","2"
"S02","12"
"S11","12"

utf8NoBOM задаёт UTF-8 без начальной метки BOM. Кавычки оформляют CSV-поля. При повторном импорте они разбираются по правилам формата, а свойства снова получают строковые значения. Числовой тип нужен на том этапе новой обработки, где требуется числовая операция. Повторный Export-Csv по тому же пути заменяет прежнее содержимое. [8], [11]

4.7 Представление на экране

Для просмотра выбранных свойств в виде таблицы служит Format-Table:

$selected | Format-Table -Property Code, Units

Команда создаёт объекты с инструкциями оформления: какие столбцы показать и как расположить их на экране. Выводящий механизм PowerShell рисует таблицу по этим инструкциям. При передаче результата Format-Table в Export-Csv экспорт получит служебные свойства оформления. Его заголовок будет содержать, например, ClassId2e4f51ef21dd47e99d3c952918aff9cd.

объекты наблюдений → Select-Object → Export-Csv → файл Code,Units
объекты наблюдений → Format-Table → вывод таблицы в терминал

Назначение конечного потребителя определяет форму результата. Свойства наблюдения сохраняются до Export-Csv; форматирование выполняется на ветви экранного просмотра. [8], пример 7

4.8 Замысел объектной оболочки

В манифесте Monad 2002 года Jeffrey Snover описал среду автоматизации, в которой инструменты передают структурированные объекты и обращаются к данным по именам свойств. Общий механизм оболочки должен был поддержать композицию инструментов администрирования. Этот замысел объясняет выбор объектной передачи в истории PowerShell. [2], [13, сс. 1–5]

В современном конвейере командлетов тип и свойства доступны следующей команде. На границе с внешними программами PowerShell работает также с текстом и байтовыми потоками. Для внешнего stdout, перенаправленного в файл или переданного другой внешней программе, в PowerShell 7.4 появилось сохранение байтового потока. Условия такого обмена описаны отдельно в документации. [5]

4.9 Пустая выборка

В inputs/no-match.csv под тем же заголовком записаны S21/3/skip и S22/8/skip. Ни одно наблюдение не проходит условие keep:

Import-Csv -LiteralPath inputs/no-match.csv -Encoding utf8 |
    Where-Object { $_.State -ceq 'keep' } |
    Export-Csv -LiteralPath results/empty.csv -Encoding utf8NoBOM
(Get-Item -LiteralPath results/empty.csv).Length

Длина равна 0. Export-Csv получил пустой вход; объекта для получения имён свойств также нет. Для сводки этого примера пустая выборка хранится файлом нулевой длины. Это результат успешно выполненного отбора.

4.10 Диагностика команды

Поток Success передаёт обычные результаты команд, в том числе объекты между стадиями конвейера. Поток Error передаёт сообщения об ошибках. Для перенаправления им соответствуют номера 1 и 2. Прочие виды сообщений имеют собственные каналы. [4]

Файла inputs/absent.csv в наборе нет.

Get-Content -LiteralPath inputs/absent.csv -ErrorAction Continue
'Команда после чтения'

При отсутствующем файле появляются сообщение об ошибке и затем указанная строка. -ErrorAction Continue разрешает продолжение после продолжаемой ошибки этого командлета. -ErrorAction Stop переводит такую ошибку в прерывающую, которую можно обработать через try/catch. Записи ошибок доступны в $Error; параметр -ErrorVariable сохраняет ошибки конкретного вызова в выбранной переменной. [3], [14, сс. 177–181]

Сообщение объясняет причину отказа. Код завершения отдельного процесса сообщает вызывающей программе его итог. Автор сценария устанавливает связь между этими двумя наблюдениями.

4.11 Сценарий обработки

Сохраним обработку в Select-Readings.ps1 в корне flowlab. Сценарий получает два пути. Вход содержит корректные записи описанного формата; каталог выхода существует и доступен. Вход и выход различны. При отсутствующем входе сценарий сообщает его имя, завершается с кодом 1 и сохраняет прежнее состояние выходного пути.

param(
    [string]$InputPath,
    [string]$OutputPath
)

if (-not (Test-Path -LiteralPath $InputPath -PathType Leaf)) {
    Write-Error "Входной файл не найден: $InputPath" -ErrorAction Continue
    exit 1
}

Import-Csv -LiteralPath $InputPath -Encoding utf8 |
    Where-Object { $_.State -ceq 'keep' } |
    ForEach-Object {
        [pscustomobject]@{
            Code = $_.Code
            Units = [int]$_.Units
        }
    } |
    Sort-Object -Property Units, Code -Culture en-US |
    Export-Csv -LiteralPath $OutputPath -Encoding utf8NoBOM
exit 0

param в начале файла объявляет параметры, [string] — их строковый тип. Test-Path -PathType Leaf проверяет наличие файла. -not обращает логическое значение, if выполняет блок при истинном условии. Двойные кавычки подставляют значение $InputPath в сообщение. Write-Error пишет в Error, exit 1 задаёт код завершения. Проверка стоит до экспорта, поэтому отсутствующий вход сохраняет выходной путь без изменений. [1, сс. 191–195]

В теле конвейера ForEach-Object сразу создаёт два нужных свойства; эта операция совмещает преобразование типа и проекцию. После штатной обработки exit 0 обозначает успех, включая пустую выборку.

Перед запуском в Windows выполните подготовку сценария для PowerShell 7. Применяются проверка действующей политики и разрешённой учебной среды, настройка Process / RemoteSigned при подходящих областях, проверка происхождения скачанного файла перед Unblock-File. Собственный файл, сохранённый локальным редактором, обычно не имеет метки интернет-загрузки.

pwsh -NoProfile -File .\Select-Readings.ps1 `
    -InputPath inputs/readings.csv -OutputPath results/selected.csv `
    2> results/selected.err
$LASTEXITCODE

pwsh -File создаёт отдельный процесс; -NoProfile исключает профили настройки. Относительные пути отсчитываются от flowlab, рабочего каталога запуска. Параметры и переменные сценария принадлежат его выполнению; после завершения дочернего процесса они исчезают вместе с ним. Значения переменных родительского сеанса сохраняются. [6], [7]

$LASTEXITCODE показывает код этого процесса. На его границе сообщения Error попадают в stderr; 2> сохраняет их в указанный файл. Для входов readings.csv, no-match.csv, absent.csv получаются коды 0, 0, 1. Используйте выходы selected.csv, empty.csv, missing.csv и журналы selected.err, empty.err, missing.err. Первые два журнала пусты, третий содержит путь отсутствующего входа. Изначально отсутствующий missing.csv после отказа также отсутствует. stdout сценария пуст: его данные записываются экспортом в файл.

4.12 Функция

Повторяющийся фрагмент можно назвать и вызывать с параметрами. Такой фрагмент называется функцией. Например, отдельное преобразование текстового количества имеет вход $Text и выдаёт целое число:

function Convert-Units {
    param([string]$Text)
    [int]$Text
}
Convert-Units -Text '12'

Результат — число 12 в Success. Выражение [int]$Text выдаёт число в выходной поток функции. Параметр $Text существует в области её вызова. Выбор функции полезен, когда одна операция повторяется в нескольких местах или получает самостоятельный интерфейс использования. [14, сс. 117–120]

4.13 Сопоставление результатов

Import-Csv -LiteralPath results/selected.csv -Encoding utf8 |
    Format-Table -Property Code, Units
Import-Csv -LiteralPath expected/selected.csv -Encoding utf8 |
    Format-Table -Property Code, Units

Сопоставьте число записей, значения и последовательность: S07/2, S02/12, S11/12. В редакторе проверьте также заголовок из двух полей Code,Units: табличный просмотр выше показывает только выбранные свойства. Допустимые CSV-кавычки и LF/CRLF могут различать байты файлов при одинаковых данных. Перестановка S02 и S11 меняет требуемый порядок.

Размер empty.csv проверяется отдельно. Для отказа проверяются код, диагностика и отсутствие нового результата.
