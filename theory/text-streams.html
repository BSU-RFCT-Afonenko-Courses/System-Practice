3  Текстовые потоки

Строки записей. Стандартные каналы. Текстовый конвейер. Отбор, сортировка, проекция. Параметры сценария. Коды завершения. Диагностика входа. Сопоставление файлов.

Программы Unix получают данные через входные каналы и выдают результаты через выходные. Оболочка fish соединяет эти каналы и направляет их в файлы. Так несколько небольших программ выполняют последовательное преобразование данных: отбор записей, упорядочение и выбор полей.

3.1 Строка записи

Лаборатория считает частицы в пробах. Код пробы, число частиц и решение проверки качества образуют запись наблюдения. Значение keep допускает наблюдение в сводку, skip исключает его. Для сравнения пригодных наблюдений требуется сводка по числу частиц; при равенстве порядок определяется кодом.

Распакуйте демонстрационный набор и откройте его каталог flowlab в терминале fish/Linux. Каталог inputs хранит входы, expected — результаты для сравнения. Создайте отсутствующий каталог results:

mkdir results
cat inputs/readings.txt
S11|12|keep
S03|4|skip
S07|2|keep
S02|12|keep

Строка — последовательность символов. В этом файле одна строка с завершающим LF представляет одну запись. Поле — отдельная часть записи: код, количество или состояние. Буквальный символ | разделяет три поля. Кодировка UTF-8 задаёт представление символов байтами; метка BOM в начале файла отсутствует.

Внутри полей нет пробелов, кавычек, разделителей и переводов строки. Код состоит из заглавной латинской буквы и двух цифр; коды уникальны. Количество — целое 0–999, записанное десятичными цифрами без ведущих нулей, кроме 0. Состояние равно keep или skip. Эти условия позволяют выделять поля по разделителю.

Файл .csv в том же наборе хранит те же наблюдения по правилам CSV для PowerShell. Текстовый маршрут использует описанный формат .txt и программы GNU grep, GNU sort и GNU cut. Все относительные пути ниже начинаются в flowlab.

3.2 Каналы процесса

У выполняющейся программы есть три стандартных канала:

Канал Номер Назначение
stdin 0 Вход данных
stdout 1 Выход результата
stderr 2 Ошибки и другая диагностика

При обычном интерактивном запуске stdin связан с терминалом, оба выхода показываются в его окне. Оболочка может назначить каналу другой источник или получатель. Перенаправление изменяет эту связь. [6, сс. 56–63]

cat < inputs/readings.txt > results/copy.txt

У cat здесь нет аргумента с именем файла: программа читает stdin. < связывает этот вход с inputs/readings.txt; > связывает stdout с results/copy.txt. Получается текстовая копия входа. В знакомой записи cat inputs/readings.txt программа сама открывает переданный путь.

2> results/read.err направляет stderr в отдельный файл. >> дописывает stdout в конец файла. Оператор > создаёт файл либо сначала сокращает существующий до нулевой длины. Поэтому сохраняемый вход и путь перенаправления должны различаться.

3.3 Соединение программ

Конвейер соединяет stdout одной команды со stdin следующей через |. В соединении передаются байты. Принимающая программа интерпретирует их согласно формату: выделяет строки, затем поля или другие элементы. [6, сс. 63–69]

readings.txt → grep → sort → cut → selected.txt
              отбор  порядок поля

Программы конвейера могут работать одновременно: следующая стадия читает поступающий поток. Операция сортировки получает весь вход, прежде чем выдать окончательно упорядоченный результат.

В статье об истории Unix Dennis Ritchie связывает появление pipes в 1972 году с предложениями Douglas McIlroy. Утилиты приспосабливали к чтению стандартного входа при отсутствии файловых аргументов. Общий способ чтения и выдачи данных позволял соединять программы в новые последовательности. [5], раздел Pipes

3.4 Отбор строк

grep '|keep$' inputs/readings.txt

grep выбирает строки, соответствующие регулярному выражению — описанию текстового образца. В обычном режиме GNU grep символ | в этом выражении обозначает буквальный разделитель, $ — конец строки. Образец выбирает строки, заканчивающиеся на |keep.

Одинарные кавычки передают образец одним аргументом. Они сохраняют символы | и $ внутри аргумента; оболочка не рассматривает этот | как соединение команд. В режиме расширенных выражений grep -E значение | меняется; показанная команда использует обычный режим.

Результат содержит строки S11, S07, S02 в исходном порядке. Во всех трёх строках сохранены код, количество и состояние.

3.5 Ключи сортировки

grep '|keep$' inputs/readings.txt |
    env LC_ALL=C sort -t '|' -k2,2n -k1,1

sort получает строки через stdin. -t '|' задаёт разделитель. Ключ сортировки — часть записи, по которой сравниваются элементы: -k2,2n выбирает второе поле целиком и числовое сравнение; -k1,1 выбирает первое поле для разрешения равенства чисел. [6, сс. 293–299]

Числовой порядок ставит 2 перед 12. При равных 12 код S02 предшествует S11. Результат этой стадии: S07/2/keep, S02/12/keep, S11/12/keep.

Локаль задаёт языковые и региональные правила, включая сравнение текста. env LC_ALL=C запускает sort с локалью C. Для используемых латинских кодов получается посимвольный порядок A–Z и 0–9. Настройка относится к этому запуску. [3]

3.6 Выбор полей

grep '|keep$' inputs/readings.txt |
    env LC_ALL=C sort -t '|' -k2,2n -k1,1 |
    cut -d '|' -f1,2 > results/selected.txt

cut -d '|' -f1,2 оставляет первое и второе поля каждой строки с разделителем между ними. Выбор части полей называется проекцией. Перенаправление записывает её результат в файл. [6, сс. 302–304]

S07|2
S02|12
S11|12
Граница Порядок кодов Поля
После grep S11, S07, S02 Code, Units, State
После sort S07, S02, S11 Code, Units, State
После cut S07, S02, S11 Code, Units

Символ | между командами управляет их соединением. Символ | внутри текстовой записи получает смысл разделителя из соглашения о данных.

3.7 Пустая выборка

Процесс возвращает код завершения — целое число, смысл которого определён программой. В показанном режиме GNU grep код 0 означает найденные строки, 1 — отсутствие совпадений, 2 — ошибку. Пустой результат отбора соответствует штатному случаю 1. [4]

В fish $status содержит код последней команды последнего конвейера, $pipestatus — список кодов его стадий слева направо. Следующий запуск обновляет эти значения, поэтому их читают или сохраняют сразу. [1]

inputs/no-match.txt содержит S21/3/skip и S22/8/skip:

grep '|keep$' inputs/no-match.txt |
    env LC_ALL=C sort -t '|' -k2,2n -k1,1 |
    cut -d '|' -f1,2 > results/empty.txt
printf 'last=%s; stages=%s\n' "$status" "$pipestatus"

Результат наблюдения — last=0; stages=1 0 0. grep не нашёл подходящих строк; sort и cut успешно обработали пустой вход. Созданный results/empty.txt имеет нулевую длину.

В формате printf %s занимает место строкового аргумента, \n обозначает перевод строки. Двойные кавычки подставляют переменные; список $pipestatus в кавычках объединяется пробелами в одну строку.

3.8 Отсутствующий вход

В наборе нет inputs/absent.txt. Проверим поведение двух программ:

cat inputs/absent.txt 2> results/read.err |
    sort > results/partial.txt
printf 'last=%s; stages=%s\n' "$status" "$pipestatus"
cat results/read.err

У cat ненулевой код, у sort — 0. Сортировка получила пустой вход. Файл partial.txt появился из-за перенаправления, хотя прочитать данные не удалось. Диагностика cat называет отсутствующий путь и сохранена в read.err; обычный конвейер соединяет только stdout.

При пустой выборке исходные данные прочитаны, но подходящих записей нет. При отсутствующем входе чтение не состоялось. Для установления причины проверяют код читающей программы и её диагностику вместе с файлом результата.

3.9 Сценарий обработки

Последовательность команд можно сохранить в файл и выполнить повторно с другими аргументами. Создайте select.fish в корне flowlab, UTF-8. Он принимает путь корректного входа и путь результата; пути различны, каталог результата существует и доступен. Проверка файла предшествует перенаправлению, чтобы отказ сохранил выходной путь без изменений. [6, сс. 382–388]

set -l input_path $argv[1]
set -l output_path $argv[2]

if not test -f "$input_path"
    printf 'Входной файл не найден: %s\n' "$input_path" >&2
    exit 1
end

grep '|keep$' "$input_path" |
    env LC_ALL=C sort -t '|' -k2,2n -k1,1 |
    cut -d '|' -f1,2 > "$output_path"
set -l stages $pipestatus

if test $stages[1] -gt 1
    exit 1
end
if test $stages[2] -ne 0; or test $stages[3] -ne 0
    exit 1
end
exit 0

$argv — список аргументов сценария; [1] выбирает первый элемент, [2] — второй. set -l создаёт локальную переменную. В fish переменные хранят списки строк. Здесь в каждой переменной пути находится одна строка.

Условием if служит команда: код 0 обозначает истинность. test -f проверяет обычный файл, not обращает результат, end закрывает блок. >&2 направляет сообщение printf в stderr. exit 1 завершает процесс с ненулевым кодом. [2]

После конвейера коды стадий сохранены в stages. У test оператор -gt проверяет «больше», -ne — «не равно». or выполняет следующую проверку, если предыдущая завершилась ненулевым кодом. Для grep допустимы 0 и 1, для следующих стадий требуется 0. Поэтому сценарий завершается успешно и при пустой выборке.

fish --no-config ./select.fish inputs/readings.txt results/selected.txt 2> results/selected.err
printf 'exit=%s\n' $status

Новый процесс fish выполняет файл; --no-config исключает файлы настройки. Его рабочий каталог — flowlab, от него разрешаются относительные пути. Созданные переменные относятся к этому выполнению; завершение дочернего процесса сохраняет переменные и рабочий каталог родительской оболочки.

Повторите вызов с inputs/no-match.txt, выходом results/empty.txt и диагностикой results/empty.err; затем с отсутствующим inputs/absent.txt, новым выходом results/missing.txt и диагностикой results/missing.err. Коды трёх вызовов — 0, 0, 1. Первые два журнала пусты, третий содержит отсутствующий путь. missing.txt перед вызовом отсутствует и после отказа не появляется. stdout самого сценария пуст; преобразованные строки записаны в файл.

3.10 Сопоставление файлов

diff -u expected/selected.txt results/selected.txt
printf 'comparison=%s\n' $status
diff -u expected/empty.txt results/empty.txt
printf 'comparison=%s\n' $status

При совпадении diff возвращает 0 и ничего не выводит. Код 1 означает различия, больший код — проблему сравнения. В выводе -u строки с - относятся к первому файлу, с + — ко второму. Здесь состав полей, порядок строк и LF входят в формат результата.
